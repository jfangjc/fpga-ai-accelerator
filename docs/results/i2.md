## Measurement interpretation

`i2_probe` reports per-layer cycles, submit-to-IRQ, IRQ-to-ready and total API
nanoseconds, plus whole-network elapsed time and instrumented cache-sync time.
At 100 MHz, cycles / 100000 = milliseconds of engine response preparation,
including stream starvation; this is not an isolated MAC-only compute counter.
DMA input overlaps engine parsing/compute. Subtracting cycle time and sync time
from wall time gives remaining host/transport overhead, not an independently
measured pure-DMA time. Report overlapping components explicitly rather than
summing them as though serial. The existing interface cannot isolate bus-active
DMA time from compute without additional instrumentation.

The original timeout probe exposed a recovery defect: resetting the engine
before stopping MM2S permitted residual packet beats to dirty the parser.

plio_dma_reset completes. This is the only software-source change. The fixed
probe passes four malformed headers with recovery, explicit reset then
byte-identical RUN_NETWORK, forced 1 ms ETIMEDOUT then successful PING, and a
new normal-deadline context with byte-identical RUN_NETWORK. Both the standalone
fixed probe and the complete runner pass these checks. No RTL was changed.
